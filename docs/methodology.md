# 방법론 (Methodology)

> 본 문서는 데이터·라벨·모델·LLM 운용의 방법론적 원칙과 그 검증 경위를
> 한곳에 정리한다. 상세 수치는 모델 카드 2종
> ([위험 모델](../reports/d2_baseline_model_card.md) ·
> [시장 상태 모델](../reports/regime_model_card.md)),
> 결정 경위 원문은 `PROGRESS.md` 를 참조.

## 1. 데이터 — point-in-time 유니버스

**분석 대상은 "그 시점에 KOSPI200 이었던 기업"이다 — 지금의 구성이 아니라.**

- 분기별 KOSPI200 구성: KRX 정보데이터시스템 분기 CSV (수동 수집,
  `data/external/kospi200_quarterly/`). 모든 외부 파일은 매니페스트
  (출처·기준일·sha256)와 함께 git 추적 — 변조 감지·재수집 가능.
- 분석 기간 내 상장폐지 종목: FinanceDataReader `KRX-DELISTING`.
- 결합 결과: **10년(2015–2024) union 321 종목**.

현 시점 구성만 쓰면 *살아남은 종목만 남는* 생존 편향이 생기고, 부실
사건(양성 클래스)이 표본에서 사라진다. 상장폐지 종목 포함이 위험 라벨의
전제다.

분석 기간은 애초 2010–2024 로 합의했으나, KRX 웹 서버가 2014-05 이전
데이터를 제공하지 않음을 가용성 검증에서 확인 → 데이터 정직성을 위해
**2015-01-01 ~ 2024-12-31** 로 단축했다 (2026-05-18 결정).

| 소스 | 용도 |
|---|---|
| DART Open API | 재무제표 (접수일 포함) |
| pykrx | 단일 종목 일간 OHLCV |
| FinanceDataReader | 상장폐지 메타·현 시점 전종목 리스트·KOSPI200 지수 |
| KRX 분기 CSV (수동) | 시점별 KOSPI200 구성 |

## 2. 룩어헤드·누수 차단

- **재무제표 사용 가능 시점 = 접수일(`rcept_dt`) + 1 영업일.**
  모든 재무 데이터 접근은 `DARTReporter` 의 시점 정렬 메서드
  (`available_at` / `latest_available`)를 단일 입구로 강제한다.
- **시간 인지 분할**: 무작위 K-Fold 금지. Expanding-window walk-forward
  + embargo gap (= forward window 365일).
- **격리 원칙 2종** (CLAUDE.md §5):
  - *유니버스 변수* (KOSPI200 편입/편출·시총 순위 등)는 피처 금지 —
    "살아남음의 함수"라 피처로 들어가면 누수 회로가 된다.
  - *상장폐지/관리종목 메타* (폐지일·사유 등)는 라벨 정의에만 사용 —
    "결과 변수"라 피처 진입 시 라벨 누수다.
- **자동 검증**: `tests/test_isolation.py` (AST 기반 3종 — 유니버스
  변수·상폐 메타·OpenDartReader 직접 호출 차단) +
  `tests/test_features_lookahead.py` (런타임 contract 4종 — reporter 가
  `t ≤ as_of` 만 받는지). CI 에서 상시 실행된다.

## 3. 위험 라벨 (D2) — 정의와 진단 사슬

**확정 정의**: *상장폐지 부실 (A=1)* ∪ *주가 drawdown 50% + 영업이익
흑자→적자 전환 (B=19)*, 1년 forward. **양성 20 (6.2%, 종목-연도 셀 기준)**.

이 정의는 선택이 아니라 **후보 전수 검증·기각 끝에 남은 입증된 최선**이다
(PROGRESS §5.5 진단 사슬 요약):

1. 관리종목 기반 라벨 (B1 v1/v2) → 검증 결과 **96% 오염** — 기각.
2. 근본 원인 식별: **KOSPI200 모집단에서 부실 사건 자체가 희소**하다.
3. KOSDAQ 확장 (B3) → 시점별 구성 확보 불가 (자동·수동 모두) →
   생존 편향 재발 위험 — 기각.
4. 신용등급 (A) → 자동 확보 불가 — 기각.
5. 상폐 부실 (A) 은 **육안 게이트로 합병 노이즈 7건 제거** 후 1건만 인정.

**알려진 한계 (정직 기록)**: (1) 양성 20건 — 통상 학습 임계(30) 미달,
(2) 양성 0년 3개 (2015·2021·2023), (3) 시간 축 불균등 — 2020 코로나
9건 편중, (4) 95%(19/20)가 B 신호 — 실질적으로 drawdown 주축 라벨.
모두 모집단 희소성에 기인한다.

## 4. 위험 모델 — 평가와 한계

- LightGBM + Platt 캘리브레이션. 피처 5종 (부채비율·유동비율·영업이익률·
  ROA + 재무제표 출처 구분) — 영업이익 *자체*는 라벨 변수라 제외, 비율
  형태만 허용.
- Walk-forward 28 fold 중 **평가 가능 fold 9** (test 양성 0 fold 는 skip).
- 5 지표: PR-AUC·ROC-AUC·Brier·ECE·Top-K precision + bootstrap CI (n=1,000).

**정직 결과** (pooled n=1,801 / 양성 37 — *평가 행* 기준, 라벨 셀 20 과
단위가 다름): **PR-AUC 0.0136 < base rate 0.0205, ROC-AUC 0.2651 < 0.5 —
모델이 random 보다 나쁘다.** 이 결과는 숨기지 않고 모델 카드와 대시보드
한계 페이지에 그대로 기록했다. 해석: 피처·모델의 실패 이전에, §3 의
모집단 희소성이 학습 가능 신호 자체를 제한한다는 **정량 증거**다.

## 5. 시장 상태 모델

- HMM (Gaussian, K=3, seed 고정) 본 라인 + GMM/K-Means 비교.
- 피처 3종: 20일 수익률·60일 변동성·변동성 비율 — rolling z-score 는
  각 시점 in-sample 통계만 사용 (룩어헤드 차단).
- **상태 라벨은 사전적(causal)으로 산출**하고, 명명(위험회피/중립/
  위험선호)만 사후에 위기 점수 순으로 부여한다.

한계 ([모델 카드 §4](../reports/regime_model_card.md)): 학술 정의와의
명명 부합 약함 · 시드 변동성 13.6% · 자동 K 선택(K=4)과의 tension ·
코로나 spot-check 부합 약함 · **전환 빈도 높음** (2,273 거래일 중 741
구간, 평균 약 3.1 거래일 — 평활화는 과거 방향 윈도 한정 후속 과제).

## 6. LLM 의 역할 — 서술 보조

LLM 은 본 프로젝트가 *직접 학습한 AI* 가 아니다 (CLAUDE.md §3.4):

- **수치·라벨을 결정하지 않는다** — 이미 검증된 수치를 입력으로만 받아
  한국어로 풀어 쓴다 (기존 사실의 변환, 새 사실 생성 금지).
- **빌드 타임 1회 배치** 로 생성해 YAML 로 고정 → **서비스 런타임
  (대시보드) 호출 0회**. `app/` 의 LLM SDK import 0 은 CI 가 검증한다.
- 프롬프트 원칙 (`src/frr/llm/interpretation.py`): 새 수치 생성 금지·
  시장 상태 조건부 해석·투자 권유 금지·일반어·2~4문장. 비율은 %로
  사전 포맷해 입력 (표기 불일치 차단).
- 공급자는 `LLMProvider` 인터페이스 뒤에 두어 교체 가능하다.

| 영역 | 한계 | 비고 |
